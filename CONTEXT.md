# Motion Commotion

Motion Commotion is a physics teaching game in which players assemble coding blocks to control an orb. Physics learning is the game's purpose.

## Language

**Orb**:
The gray ball whose motion results from running a block program.

**Block program**:
An ordered arrangement of coding blocks that specifies the orb's actions.

**Snap connection**:
The visible connection between successive executable blocks, where one block's bottom connector meets the next block's top connector.

**Force block**:
A formula block that applies a single kick to the orb. Each force block requires its own immediately preceding direction block.

**Equation Blocks palette**:
The palette section containing the five predefined equations. Each equation can be used as an equation command or as a compatible nested formula.

**Equation tile**:
A predefined equation available in Blocks. According to the equation and its placement, it supplies a compatible value or creates an executable action in Active.

**Equation command**:
An equation block placed in Active that applies a physical effect when execution reaches it.

**Velocity command**:
An equation command that replaces the orb's velocity with its calculated velocity.

**Acceleration command**:
An equation command that sets an ongoing acceleration alongside gravity. A later acceleration command replaces it; zero turns it off.

**Position command**:
An equation command that instantly places the orb at its calculated position.

**Palette template**:
An editable starting configuration for new copies of a block. Changing it leaves existing copies unchanged, while ball mass remains shared.

**Weight block**:
A block based on W = mg that changes ongoing gravity when executed, without applying an additional kick. A nested weight formula supplies a force value without changing gravity.

**Ball mass**:
The orb's physical mass, initially 1 kg. Editable mass inputs change this physical property.

**Direction block**:
A block that specifies the direction of its immediately following Velocity, Acceleration, Position, or Force command. Zero degrees points right and 90 degrees points up.

**Wait block**:
A block that delays program execution for a duration in seconds.

**Formula output**:
The fixed quantity on the left side of a predefined equation. Its value comes from the editable inputs on the right side.

**Formula input**:
A manipulatable right-side value supplied by a number or a compatible nested formula block.

**Nested formula**:
A formula whose output supplies a compatible input of another formula.

**Equation edit button**:
The pencil-with-sparkles affordance associated with one equation and its future edit menu. It is distinct from the equation's numeric inputs.

**Equation editing**:
Changing the form of an equation, as distinct from changing its numeric input values.

**Formula variant**:
An explicitly supported arrangement of a base equation with a fixed left-side output. Variants are curated rather than generated by symbolic rearrangement.

**Level**:
A team-authored physics puzzle played using the game's mechanics.

**Placeholder level**:
A temporary gap-crossing environment used to exercise the player interface and level outcomes before teammates replace it with an authored puzzle.

**Landing target**:
The marked destination region for the orb. The entire colored strip is valid; its colors do not award different scores in the current scope.

**Attempt**:
One execution of a block program toward a level objective. It succeeds on a valid landing and fails if the orb falls out of bounds or the program ends before reaching the target.

**Successful landing**:
Contact by the orb with the top of the landing target from above. Side or underside contact does not count, and remaining at rest is not required.

**Program completion**:
Reaching the end of a block program, which freezes simulation time. An attempt that completes without a successful landing fails.

**Level editor**:
The authoring tool teammates use within Unity to build levels.

**Foundation**:
The reusable game mechanics and authoring capabilities on which the team builds levels.
_Avoid_: First level, campaign

**Mechanics proof of concept**:
A minimal demonstration used to establish that a mechanic works. It is not a designed level.
_Avoid_: Playable level
