# Motion Commotion

Motion Commotion is a physics teaching game in which players assemble coding blocks to control an orb. Physics learning is the game's purpose.

## Language

**Orb**:
The gray ball whose motion results from running a block program.

**Block program**:
An ordered arrangement of coding blocks that specifies the orb's actions.

**Snap connection**:
The visible connection between successive executable blocks, where one block's bottom connector meets the next block's top connector.

**Force block**:
A formula block that applies a single kick to the orb. Each force block requires its own immediately preceding direction block.

**Equation Blocks palette**:
The palette section containing predefined equations and the formula variants created during the current level visit. Variants provide executable actions or compatible nested values according to their solved quantity.

**Equation tile**:
An equation template available in Blocks. According to its solved quantity and placement, it supplies a compatible value or creates an executable action in Active.

**Equation command**:
An equation block placed in Active that applies a physical effect when execution reaches it.

**Velocity command**:
An equation command that replaces the orb's velocity with its calculated velocity.

**Acceleration command**:
An equation command that sets an ongoing acceleration alongside gravity. A later acceleration command replaces it; zero turns it off.

**Position command**:
An equation command that instantly places the orb at its calculated position.

**Palette template**:
An editable starting configuration for new copies of a block. Changing it leaves existing copies unchanged, while ball mass remains shared.

**Weight block**:
A block based on W = mg that changes ongoing gravity when executed, without applying an additional kick. A nested weight formula supplies a force value without changing gravity.

**Ball mass**:
The orb's physical mass, initially 1 kg. Editable mass inputs change this physical property.

**Direction block**:
A block that specifies the direction of its immediately following Velocity, Acceleration, Position, or Force command. Zero degrees points right and 90 degrees points up.

**Wait block**:
A block that delays program execution for a duration in seconds.

**Formula output**:
The read-only quantity isolated on the left side of an equation. Its value comes from the editable inputs on the right side. Rearranging an equation changes which variable is its output.

**Input draft**:
The text currently being edited before it is accepted as a numeric value.

**Committed input**:
A numeric value accepted by validation for formula evaluation and execution.

**Formula input**:
A manipulatable right-side value supplied by a number or a compatible nested formula block.

**Nested formula**:
A formula whose output supplies a compatible input of another formula.

**Equation edit button**:
The pencil-with-sparkles control in Blocks that opens editing for its associated equation. It is distinct from the equation's numeric inputs.

**Equation editing**:
Changing the form of an equation, as distinct from changing its numeric input values.

**Formula variant**:
An explicitly supported arrangement of a base equation with a fixed left-side output. A motion-time variant also identifies its earlier or later solution. Variants are curated rather than generated by symbolic rearrangement.

**Level**:
A team-authored physics puzzle played using the game's mechanics.

**Placeholder level**:
A temporary gap-crossing environment used to exercise the player interface and level outcomes before teammates replace it with an authored puzzle.

**Landing target**:
The marked destination region for the orb. The entire colored strip is valid; its colors do not award different scores in the current scope.

**Attempt**:
One execution of a block program toward a level objective. It succeeds on a valid landing and fails if the orb falls out of bounds or the program ends before reaching the target.

**Successful landing**:
Contact by the orb with the top of the landing target from above. Side or underside contact does not count, and remaining at rest is not required.

**Program completion**:
Reaching the end of a block program, which freezes simulation time. An attempt that completes without a successful landing fails.

**Level editor**:
The authoring tool teammates use within Unity to build levels.

**Foundation**:
The reusable game mechanics and authoring capabilities on which the team builds levels.
_Avoid_: First level, campaign

**Mechanics proof of concept**:
A minimal demonstration used to establish that a mechanic works. It is not a designed level.
_Avoid_: Playable level


**Speed cap**:
A configurable limit on the ball's actual vector speed. Large valid equation values remain unchanged. Reaching the cap keeps play running and shows a fading red warning. Default 100 m/s. See [input validation](docs/design/input-validation.md).


**Map zoom**:
Player-controlled camera magnification from map-only wheel or two-finger pinch input. It never changes physics or simulation time. Sidebar reflow preserves zoom; Reset restores the level or Sandbox default. See [map camera zoom](docs/design/map-camera-zoom.md).


**Camera pan**:
Moving the view across the map without moving game objects or changing magnification.


**Free view**:
A camera view positioned manually instead of automatically following the ball. Manual panning enters Free view; the Center camera action returns to Follow view.

**Follow view**:
The camera mode that uses the ball's normal gameplay framing. It is suspended by manual panning and restored by the Center camera action.

**Center camera**:
Returning the view to the current ball's normal follow framing while preserving magnification and the experiment state. Recentring resumes Follow view and can reach a ball outside the map's camera bounds.


**Outcome screen**:
The screen shown after a level attempt ends, offering the player's next actions.

**Controls menu**:
The menu where players look up the game's controls and their corresponding actions.


**Retry**:
Returning the current level attempt to its starting state for another try, keeping the player's program available to edit before running again.


**Mass command**:
An equation command that assigns its calculated mass to the orb while preserving velocity.

**Displacement command**:
An equation command that moves the orb by a directed distance from its current position.

**Velocity-change command**:
An equation command that adds a directed change to the orb's current velocity.

**Gravity command**:
An equation command that directly sets downward gravity.

**Equation editor draft**:
The unconfirmed symbolic arrangement being edited before it becomes a reusable formula variant.

**Time branch**:
The earlier or later solution chosen for a motion equation solved for time. The choice remains part of the formula variant when its numeric inputs change.


**Level visit**:
The period from entering a level until leaving it. Retrying or replaying an attempt stays within the same visit.

**Created equation**:
A formula variant added to Blocks through the equation editor. It remains available for unlimited copies during the current level visit.

**Initial-condition value**:
An initial position or velocity used in a calculation. Calculating such a value does not itself change the orb's current state.
